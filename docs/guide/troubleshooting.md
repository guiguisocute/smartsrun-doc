# 故障排查与认证页采集

| 现象 | 优先检查 |
| --- | --- |
| 安装后没有菜单或页面报模块缺失 | 包型、依赖、Lua CBI 兼容性；重新登录 LuCI |
| 无法连接 Wi-Fi | SSID、无线密码、信号、无线电占用、企业认证及未应用的 UCI 修改 |
| 已连接 Wi-Fi，但无 IPv4 | DHCP、出口接口、防火墙与校园接入限制 |
| 已能上网，未发现认证地址 | 指定登录页或选择学校预设后继续探测；互联网连通性不提供网关地址本身 |
| 认证后缀为空或未读取到 | 认证页是否公开选项、预设是否记录；使用手动输入或网页采集 |
| 账号归属未能判断 | 该账号是否在线、网关是否返回账号/域信息、是否在相同线路；这不是后缀枚举结果 |
| 密码错误或认证拒绝 | 实际完整登录名、账号状态、密码与 `AC_ID`，不要将错误视为验证成功 |
| 网关可达，互联网不可达 | 网页认证结果、探测目标、当前线路和路由，结合具体错误排查 |
| 手动登出后再次上线 | Go 开发版会暂停该账号的自动认证；检查是否有其他客户端维持登录，或之后是否保存了新配置。1.x 版本检查自动认证是否仍开启 |
| 多 WAN 某条线路失败 | 该账号的接口、IPv4、设备和认证参数，不以其他 WAN 在线代替判断 |
| 开启 UA-Mask 本机代理后认证超时 | 检查认证网关是否被重定向；Go 开发版的验证范围和处理方式见下文 |
| 无线任务未完成回滚 | 是否有并发网络修改；依据提示检查 network / wireless / firewall |

提供问题信息时包含插件版本、固件与包管理器、接入方式、失败步骤、经过脱敏的相关日志。Wi-Fi 与校园认证使用不同密码；同一账号被其他客户端维护时可能相互抢占会话。

## Go 开发版与 UA-Mask

2026-09-20 在 OpenWrt 25.12.2 x86_64 虚拟机中，使用实际 UA-Mask 0.4.3 安装包（[固定源码版本](https://github.com/Zesuy/UA-Mask/tree/83846d3780b1e30f87816310ae75d95798a5bd4d)）和两个隔离的模拟认证网关验证了以下组合。结果对应 Go 开发版，不代表现有 1.x 发布版或校园检测效果。

| UA-Mask 设置或操作 | 已观察结果 |
| --- | --- |
| 不代理本机流量，`proxy_host=0` | 两条独立 WAN 的本机认证正常；LAN 客户端的 HTTP 对照请求仍按设置改写 |
| 代理本机流量，仅绕过各认证网关的精确 IPv4 地址 | 两条 WAN 认证正常；本机和 LAN 的其他 HTTP 对照请求仍被 UA-Mask 改写 |
| 代理本机流量，认证网关也被重定向 | 两条 WAN 均在获取 challenge 时超时，没有继续发送登录凭据 |
| UA-Mask 重启、崩溃后由自身服务恢复、fw4 重载 | 配置精确网关绕过时，两条 WAN 可恢复认证，未观察到反复登录风暴 |
| smart-srun 停止、启动，或通过 apk 卸载后重新安装 | UA-Mask 的配置、规则和运行进程保持不变，LAN 对照请求仍被改写 |
| 两条 WAN 使用相同网关地址和相同本机 IPv4 | 关闭本机代理或精确绕过网关时，各账号只到达所属网关；断开 A 后不会借 B 登录，B 仍可认证 |
| 精确网关绕过开启，断开 WAN A | A 的认证失败且未向任一网关提交登录凭据；B 仍可认证，LAN 对照请求继续改写；恢复 A 后可重新认证 |
| 获取 challenge 期间更换 WAN A 的 IPv4 | 旧请求中断且未提交登录凭据；新地址可重新认证，B 和 LAN 对照请求仍正常，无需重启 smart-srun |
| HTTPS 认证网关 | 有效证书和对应域名可认证；不受信或域名不匹配的证书在发送认证请求前被拒绝 |
| DNS 响应截断或超时 | 截断后使用 TCP 查询；A 线 DNS 超时会有界失败，B 仍可认证，A 的 DNS 恢复后可重试 |
| DNS 被透明 DNAT 到本机 dnsmasq 代理 | 代理可能从 B 线重新发起 A 线查询；本次实验随后认证失败且未提交登录凭据。精确排除 A 线 DNS 的重定向后，查询和认证恢复到 A |
| 连通性探测返回重定向、HTML 或慢响应 | 已认证与互联网可用分别显示；不会跟随重定向发送凭据，探测恢复 204 后可确认连通 |

若只有开启本机代理后认证失败，可在 **UA-Mask 自身的绕过 IP 设置**中添加实际认证网关的单个 IPv4 地址（`/32`）；多 WAN 分别填写各自网关。另一种方式是关闭 UA-Mask 的本机代理，保留其 LAN 代理设置。修改后分别测试认证和原本需要 UA 改写的业务。smart-srun 不会自动改写 UA-Mask 的规则。

如果使用透明 DNS 代理，多 WAN 还需在该代理的设置中，为所选线路的实际 DNS 地址精确排除 UDP/TCP 53 端口的重定向；只绕过 HTTP 认证网关不足以保证 DNS 出口。Go 开发版只获得本机回环 DNS 时会明确拒绝域名解析，要求配置该线路上可达的 DNS。smart-srun 不会自动修改用户的 DNS 或代理规则。

不要为此放行所有 80 端口、清空防火墙或取消 smart-srun 的出口绑定。实验分别覆盖了不同 WAN 子网，以及网关和本机 IPv4 都相同的隔离线路；本地 DNS 代理实验使用 dnsmasq 2.91，其他代理、iptables 与真实校园环境仍需分别验证。这些实验不证明 Wi-Fi 切换时游戏连接能够保持。

Go 开发版手动登出后，即使网关未能确认退出，该账号的自动认证也会保持暂停；手动登录可恢复。这个暂停跨服务重启保留，保存新配置会重新按配置执行。网关会话是否真正退出仍应以登出结果为准。

## 参数收集与问题反馈

优先使用插件的一键配置：先选择接入线路，探测认证地址和后缀，再填写账号。保存成功后可生成预设 Issue 草稿，操作说明见 [贡献学校预设](/contribute/presets)。

插件不能执行任意门户 JavaScript。对于动态选项、特殊编码或未公开后缀的页面，可手动填写已知值；若浏览器能登录而插件不能，请通过 [学校不适配反馈](https://github.com/matthewlu070111/smart-srun/issues/new?template=%E2%9D%8C-%E5%AD%A6%E6%A0%A1%E4%B8%8D%E9%80%82%E9%85%8D.md) 提供页面地址、出错步骤与脱敏日志。

需要进一步诊断时，可在浏览器开发者工具中核对正常登录请求的 `ac_id`、用户名后缀和登录参数。不要公开完整 HAR、Cookie、密码、challenge、token、`info`、`chksum` 或未经检查的原始响应。浏览器登录成功不代表插件已经适配，应分别说明结果。
